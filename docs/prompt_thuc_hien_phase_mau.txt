B. XÁC ĐỊNH PHASE
==================================================

Từ PHASE_NUMBER:

1. Tìm đúng section phase trong docs/phases.md.
2. Xác định:
   - Tên phase.
   - Mục tiêu phase.
   - Phạm vi chức năng.
   - Backend checklist.
   - Frontend checklist.
   - Database checklist.
   - Test checklist.
   - Responsive checklist.
   - Exit checklist.
   - Dependency với phase trước.
   - Tag/version checkpoint dự kiến.
3. Không thực hiện nội dung thuộc phase sau.
4. Không tự mở rộng phạm vi ngoài checklist.
5. Nếu phase trước chưa đạt Exit Checklist, phải báo blocker trước khi code.

Quy ước số phase:

- PHASE_NUMBER = 1 tương ứng Phase 1.
- Khi đặt branch, tự chuẩn hóa thành 01 nếu docs/git-phases.md yêu cầu.
- Không bắt người dùng đổi 1 thành 01.

==================================================
D. KIẾN TRÚC BACKEND BẮT BUỘC
==================================================

Backend có các project:

- GroceryStore.Api
- GroceryStore.Application
- GroceryStore.Domain
- GroceryStore.Infrastructure
- GroceryStore.Persistence

Tuân thủ dependency:

- Domain không phụ thuộc project nào.
- Application chỉ phụ thuộc Domain.
- Infrastructure phụ thuộc Application và Domain.
- Persistence phụ thuộc Application và Domain.
- Api gọi Application và đăng ký Infrastructure/Persistence.

Quy tắc:

1. Api:
   - Controller hoặc endpoint.
   - Authentication.
   - Authorization.
   - Middleware.
   - Request/response HTTP.
   - Không chứa business logic.
   - Không truy cập DbContext trực tiếp.

2. Application:
   - Use case.
   - Command/query.
   - Handler.
   - DTO.
   - Validator.
   - Interface cho dịch vụ ngoài.
   - Không phụ thuộc implementation từ Infrastructure.

3. Domain:
   - Entity.
   - Value Object.
   - Enum.
   - Domain Event.
   - Business invariant.
   - Domain exception.
   - Không phụ thuộc EF Core, HTTP, SMTP, R2 hoặc Goong.

4. Infrastructure:
   - SMTP.
   - SMS OTP.
   - Cloudflare R2.
   - Goong Maps.
   - Dịch vụ bên ngoài.
   - Không chứa nghiệp vụ cốt lõi.

5. Persistence:
   - ApplicationDbContext.
   - EF Core configuration.
   - Migration.
   - Interceptor.
   - Transaction.
   - Repository đặc thù.
   - Seed reference data.

F. BUSINESS RULE BẮT BUỘC
==================================================

Tuân thủ toàn bộ rule trong tài liệu, đặc biệt:

1. Email hoặc số điện thoại phải có ít nhất một.
2. Tài khoản chưa xác minh không được sử dụng.
3. Không dùng float hoặc double cho tiền.
4. Tiền dùng decimal.
5. Khối lượng rau có bước 0,1 kg.
6. Tiền mặt làm tròn lên 1.000 đồng.
7. Chuyển khoản dùng số tiền chính xác.
8. Không cho tồn kho âm.
9. Xuất kho theo FEFO.
10. Checkout online giữ tồn trong 10 phút.
11. Checkout và POS phải dùng database transaction.
12. Giá, tổng tiền, phí ship và tiền thừa phải được backend tính lại.
13. Không tin dữ liệu tiền từ frontend.
14. Ảnh lưu Cloudflare R2.
15. SQL Server chỉ lưu metadata và object key ảnh.
16. Đơn online mặc định được bật.
17. Đơn dưới hoặc bằng 5 km dùng phí ship cơ bản theo cấu hình.
18. Khoảng cách dùng Goong Maps API.
19. Khách vãng lai tại quầy không bắt buộc tạo tài khoản.
20. Hàng dễ hư không được trả vì đổi ý.
21. Không xóa cứng dữ liệu đã được tham chiếu trong lịch sử.
22. Mọi cập nhật nhạy cảm phải kiểm tra authorization ở backend.

==================================================
G. DATABASE
==================================================

1. EF Core Migration quản lý schema.
2. Không tự sửa migration cũ đã được áp dụng.
3. Tạo migration mới khi schema thay đổi.
4. Mỗi foreign key phải có delete behavior rõ ràng.
5. Thêm index cho:
   - Foreign key thường xuyên truy vấn.
   - Email chuẩn hóa.
   - Số điện thoại chuẩn hóa.
   - SKU.
   - Barcode.
   - OrderCode.
6. Filtered unique index cho field nullable cần unique.
7. Dùng rowversion cho entity có nguy cơ cập nhật đồng thời.
8. database/seed.sql chỉ dùng trước release.
9. seed.sql phải idempotent.
10. Không chèn PasswordHash thủ công bằng SQL.
11. Tài khoản demo phải tạo qua ASP.NET Core Identity/UserManager.
12. Không đưa secret vào seed.sql.

==================================================
H. NAMING CONVENTION
==================================================

Tuân thủ docs/naming-convention.md.

C#:

- Constant: UPPER_SNAKE_CASE.
- Class, struct, property, method, enum: PascalCase.
- Interface: IPascalCase.
- Private field: camelCase, không có prefix underscore.
- Parameter và local variable: camelCase.
- Một file C# chứa một public type chính.
- Tên file trùng tên type chính.

Frontend:

- React component: PascalCase.
- Hook: useCamelCase.
- Function, variable: camelCase.
- Constant: UPPER_SNAKE_CASE nếu là constant thực sự.
- CSS: kebab-case/BEM.
- API route: plural kebab-case.

Không dùng:

- Hungarian notation.
- Tên viết tắt khó hiểu.
- Magic number.
- God class.
- Generic name như Helper, Utils, Manager nếu không thể hiện trách nhiệm rõ.

==================================================

Thực hiện checklist theo thứ tự dependency.

Với mỗi checklist item:

1. Xác định acceptance criteria.

- Migration chạy thành công.

- Screenshot hoặc mô tả manual verification.
- SQL constraint/index được kiểm tra.
